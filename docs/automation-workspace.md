# 自动化工作区路线

## 设计基线

- 自动化定义继续使用现有原生自动化卡片 JSON，避免另建格式。
- `steps` 是执行节点；`flow.start` 与 `flow.edges` 是流程入口和有向边。条件边使用 `true` / `false`，回边表达循环，循环由 `limits.maxTransitions` 限制。
- `flow.layout` 只保存画布坐标，不参与执行。
- 流程节点中的 MCP 调用复用 AI 当前工具目录和 `BrowserAutomationBridge` MCP router。AI 的 `manage_card` 与首页列表操作访问同一个存储对象。
- 外部 MCP 和本地 AI 共用 `manage_card` action 契约。AI 先读取卡片 `inputSchema` 再提交输入；MCP 流程节点可从当前工具目录选工具并按顶层 schema 编辑参数，保留 JSON 编辑作为复杂/未知 schema 的回退。
- 每次执行必须绑定已连接的 AI-FREE Chromium 浏览器连接；不接受系统浏览器或外部路径。
- 运行详情使用文本节点并默认脱敏，避免把输出解释为 HTML。

## 阶段

### 第一阶段：工作区纵向切片

完成首页自动化入口、流程列表、浏览器选择、新建/编辑画布、节点拖动与连线、条件分支与循环回边、JSON 导入导出、版本查看、后台运行列表、步骤进度、输出脱敏、停止和失败重试。执行继续使用已有 `start_run`、`automation-runs.json` 和 MCP router。

### 第二阶段：执行控制与恢复

运行器已支持步骤边界暂停/继续和单步放行；回收站通过兼容字段 `deletedAt` 实现，默认列表隐藏已删除流程，支持恢复和永久删除。永久删除在首页需要本机确认，在外部 MCP 和 AI 侧栏需要接管在线浏览器。旧卡片缺少该字段时仍视为有效卡片。暂停是进程内控制；取消/超时会等当前浏览器操作返回后才完成，不能回滚已经发生的页面副作用，也不会继续后续步骤。运行输入仅供当前进程幂等判断和失败重试，磁盘历史不保存原始输入；应用退出后未结束的运行标记为中断，不自动重放浏览器动作，历史运行不能直接重试。只有可重试失败可用 `retry_run` 从头执行；成功、取消、超时和结果未知的运行需查看详情后重新提交为新运行。

尚待本阶段补齐：运行输入表单、失败节点定位/恢复策略的 UI、并发运行与退出恢复的集成验证及后台执行租约回归。新写入的卡片版本保存并执行对应的 `inputSchema`。缺少快照的旧历史版本使用兼容规则。当前“重试”会新建一次完整流程运行，不代表从失败节点续跑；浏览器副作用可能已生效时禁止隐式续跑。

### 第三阶段：AI 可治理的自动化操作

现有 MCP 卡片管理接口已支持 AI 读写、校验、版本操作、恢复/删除与执行首页共享对象。仍待实现的是对创建、更新、删除、恢复和执行写入有界审计记录，保留操作者、动作、对象 ID、版本摘要和时间，不保存凭据或原始敏感输出。执行授权保持当前接管规则；流程级细粒度确认/限制策略仍未实现。

### 第四阶段：编辑器与流程能力完善

增加撤销重做、复制粘贴、缩放/小地图、结构校验与错误定位、节点工具 schema 选择器、变量检查和更丰富的条件/循环表达。新能力必须进入共享定义校验器和执行器；不得在 renderer 另写一套运行语义。

## 当前实现边界

第一阶段提供节点 JSON 属性编辑、浏览器工具 MCP 节点模板和条件/回边连接。编辑器现可按已发现工具 schema 选择 MCP 工具并编辑常见顶层参数，未知或复杂 schema 可回到 JSON。第二阶段已提供暂停、继续、单步及回收站恢复/永久删除。完整 AI 操作审计与视觉撤销历史属于后续阶段；运行输入表单和失败节点恢复策略仍未实现。
