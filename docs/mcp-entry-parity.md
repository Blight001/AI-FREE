# 外部 MCP 与 AI 控制侧栏一致性

本文记录同一版本中两个入口的能力、执行差异和验收顺序。外部入口指本机 `/mcp/v1` 客户端。内置入口指「AI 控制」侧栏提交给模型的 `localInteraction` 工具。HeySure 设备注册和自动化卡片执行器是相邻调用方，涉及共享逻辑时纳入回归。

## 共同契约

- 在相同授权、浏览器能力、活动文档和等效输入下，共享工具使用相同的参数含义、可执行目标、业务结果、错误码、可重试语义及副作用。HTTP 的 JSON-RPC 与图片块、侧栏的模型消息与工具时间线分别适配传输和展示。
- 工具目录、面向模型的说明、观察返回值和实际分派必须由同一能力规则约束。可用性受授权、内核或场景限制时，由主进程判定，并为调用者提供一致的原因和恢复方式。意图筛选只负责缩减提示上下文，权限必须在执行边界落实。
- 页面令牌绑定到实际文档，工作区路径和文件摘要在主进程验证。带副作用的调用以 `未执行`、`已派发`、`业务已验证` 或 `结果待核验` 区分状态。结果未知时先读回。接管、主动切页、停止、窗口关闭和断连需要覆盖两个入口。
- 相同模型比较时固定模型版本、工具目录、提示、权限、视口及网页状态。自动回归先用确定性工具调用验证两端语义，再从真实侧栏和外部 MCP 各自完成任务。调用次数、时间、站点回执一起记录。

## 执行路径与收敛位置

| 调用方 | 当前执行路径 | 收敛位置 |
| --- | --- | --- |
| 外部 MCP | 网关校验授权、选择浏览器，经 AutomationBridge 发往原生服务。浏览器调用携带超时，未绑定本次操作的文档身份。 [外部网关](../src/app/backend/services/browser-automation-external-gateway.js) | 网关传入已验证的调用方身份、授权与生命周期。共享执行层持有文档身份与操作范围。HTTP 和 stdio 继续通过同一网关。 |
| AI 控制侧栏 | 工具上下文生成模型目录，工具执行器选择目标，侧栏目标校验捕获文档身份。原生服务收到该身份后进入 `dispatchBound`。 [目录](../src/app/backend/features/ai-chat/chat-tool-context.js) · [执行器](../src/app/backend/features/ai-chat/chat-tool-executor.js) · [目标校验](../src/app/backend/features/ai-chat/chat-browser-target.js) | 共享能力规则同时驱动目录和执行。侧栏适配本轮取消、文件选择确认界面和模型消息。 |
| 自动化卡片与 HeySure | 卡片步骤经独立 MCP 路由。HeySure 设备调用复用外部目录和分派入口。 [卡片路由](../src/app/backend/services/automation-card-mcp-router.js) | 卡片单步复用共享执行契约。设备适配保留公开工具名和文件引用行为。用已有卡片和设备用例验证迁移。 |

页面绑定路径上的限制按工具、`action` 和 `surface` 核对。当前绑定分支对 `browser_file` 只接受 `download_element` 和 `upload`。直接下载、工作区元信息、保存登录会话和服务器文件引用分别判定文档要求与授权。图片免确认仅影响确认步骤，文档、路径和字节校验继续执行。站点收件回执单独核验。 [原生页面校验](../src/app/backend/services/native-browser-page-binding.js) · [侧栏上传校验](../src/app/backend/features/ai-chat/chat-browser-upload.js)

## 当前目录和差异

账号工具可用且已连接 Chromium 时，包含浏览器环境意图的侧栏目录与外部目录各有 14 个工具。13 个同名工具的参数结构已在集成测试中比对。路由参数的说明文字由入口适配。无环境配置意图时，侧栏省略 `browser_environment`。首页开发者模式的 MCP 目录展示总工具集，实际可用性仍取决于入口和运行状态。

| 工具 | 当前双入口行为 | 核对与整改 |
| --- | --- | --- |
| `browser_control` | 两端共用接管、状态和释放。外部网关可在无 Chromium 连接时调用 `overview`，侧栏目录和路由依赖连接。外部按活动栏目的变化同步默认连接，侧栏按本轮目标和显式选择路由。 | P1。将只读总览做成同一全局能力。二窗口、无连接和显式选中窗口离线时覆盖两个入口。 |
| `browser_tab` | 两端共用 Chromium 标签命令。侧栏记录切换后的文档并从模型结果移除 `pageToken`。外部 `list` 当前直接返回原生结果中的 `pageToken`。 | P1。将文档身份保存在主进程。统一公开标签字段，先确认现有外部客户端兼容性。验证同 URL 刷新、切换后旧引用失效以及不允许跨入口误用引用。 |
| `browser_observe` | 共用观察及辅助功能补全。侧栏将观察关联到本轮绑定文档。Nova Reel 的 `file-input` 返回空集合，辅助功能补全给出的引用缺少侧栏上传能执行的定位。 | P0。共用可执行控件判断和返回格式。验收透明控件、关联 `label`、遮挡、禁用、窄视口和观察过期。 |
| `browser_action` | 侧栏页面调用走 `browserActionRaw`。外部单步先经过 `BrowserWorkflow.action`，该层处理探测、断言和报告。公共 schema 还列出页面以外的 `surface`，这两个入口对该类调用都有限制。 | P1。按动作核对参数、`after`、业务断言、不可执行和结果未知的语义。能力目录明确表面支持范围，验证两端都不会重复执行提交。 |
| `browser_wait` | 共用等待服务。侧栏附文档令牌，固定时长等待结束时还会验证文档。外部无该令牌，等待可以跨活动文档变化。 | P1。同页等待和等待导航使用清晰的条件。验证取消、超时和切页的返回，避免把等满时长当成条件成立。 |
| `browser_screenshot` | 共用 Chromium 截图。外部将截图包装为 MCP 图片块，侧栏转成模型图像消息及时间线元数据。侧栏附文档令牌，且图片是否可供模型读取受模型配置影响。 | P1。比对同页截图尺寸、可读像素、图像能力协商及错误。保留两端各自的传输格式。 |
| `browser_file` | 图片元素下载和可执行文件控件在隔离夹具中已通过双入口。外部可按 URL 下载，侧栏绑定分支拒绝。侧栏上传重新校验文件并绑定选择 ID，外部走另一条选择器执行路径。`save_session`、`upload_to_server` 等动作也需逐个审核适用权限。 | P0。优先统一已观察下载链接与上传控件，保留页面身份、文件摘要、接管和站点回执。覆盖错误文件、页面切换、重复提交以及无回执。高权限文件动作单独声明授权。 |
| `browser_media` | 两端共用发现服务，下载复用 `browser_file download_element`。外部可能走已观察媒体地址的软件下载回退，带页面令牌的侧栏使用原生元素分支。 | P0。随文件服务一起核对视频、音频和直链。确认公开返回的 `downloadable` 对当前授权和内核确实成立。 |
| `manage_card` | 两端目录都提供。外部可进入卡片服务，侧栏浏览器路由的允许集合不包含该工具。卡片执行还经独立的 `AutomationCardMcpRouter`。 | P1。分别路由查询、编辑和运行。用已有卡片服务及执行器承接，覆盖持久数据和卡片回读兼容。每个步骤复用适用的 MCP 操作契约。 |
| `browser_workflow`、`browser_page_batch` | 外部目录有 `browser_workflow`。侧栏隐藏它并提供 `browser_page_batch`。两者在步骤类型、断言、暂停恢复、失败反馈和生命周期上不同。 | P2。先确定产品支持的批处理能力及各入口能力边界。核对旧客户端和保存的卡片。优先复用单步执行及错误语义，再处理编排层。 |
| `windows_tab` | 共用软件栏目工具。外部网关和侧栏分别同步各自的目标选择状态。 | P1。覆盖打开、关闭、焦点切换和并发入口。验证关闭已选目标后两端遵循明确的重新选择规则。 |
| `browser_environment` | 共用环境服务。外部目录常驻，侧栏按意图注入。 | P2。用隔离 Profile 验证脱敏读回、增量修改、重启及未改字段保留。权限和输入验证由共享服务执行。 |
| `account_manage` | 账号库存在时两端共用工具，包括脱敏及本机确认。侧栏可传本轮停止信号，外部直接使用共享服务。 | P2。覆盖脱敏、撤销、确认取消及断连。账号引用和填写期限与浏览器目标一并核对。 |
| `run_command` | 两端共用进程执行。侧栏有输出流、停止信号及历史摘要，外部等待工具结果。 | P2。比对退出码、截断、时限和进程树回收。先定义外部请求取消与进程所有权，再实现两端等效取消。 |

## 实施顺序与交付门槛

1. **P0 文件链路。** 使用隔离页面还原 Nova Reel 的下载链接、加号关联控件及窄侧栏布局。两端分别下载同一份 PNG，将工作区路径和摘要交给上传，核对页面收件字节和一次提交。只在页面输出业务回执后保存结果证据。并行验证换标签、刷新、文件被替换、断开和回执丢失。
2. **P1 浏览器执行。** 核对总览、目标选择、标签、观察、动作、等待和截图。让共享服务拥有文档校验、能力描述和操作结果。用现有桥接层装配授权及不同传输。将无浏览器目标、过期观察、不支持动作等失败注入同一组双入口测试，再接入卡片的可用性检查。
   - 交错验收由两端先后观察同一文档，再分别使用各自的引用。任一入口的新观察只更新其会话的引用集合。同一 URL 刷新出新文档后，两边的旧引用均失效。接管仍由共享服务约束。
3. **P2 软件工具与编排。** 在隔离账号库和 Profile 验证窗口、账号、环境、命令和卡片。先核对所有者、并发和持久化，再决定批处理与工作流的收敛范围。保留公开工具名和兼容字段，明确每个过渡分支的移除条件。
4. 将双入口对照加入相关 MCP 改动的验收。目录和 schema 优先走确定性集成测试。页面动作走真实 Chromium。侧栏的工具调用及模型图像输入走真实 Electron。涉及 HTTP、stdio 或打包资源时覆盖对应入口。输出两端的业务结果、差异和未覆盖项。

## 二阶与三阶影响

- **用户行为。** 工具宣称可用却失败会诱导模型换选择器、反复重试或绕去 `run_command`。统一观察和错误回执后，模型能在证据不足时停在正确步骤，减少误提交和重复操作。验收记录无效重试数与站点提交次数。
- **并发及安全。** 外部与侧栏同时操作会竞争原生指针、活动标签、接管和文件选择。统一校验可能改变外部客户端对自动跟随标签的预期。观察缓存当前以连接 ID 为键，两端观察会更新同一个最新引用集合。将文档、观察 ID 和调用方会话的所有权纳入双入口并发测试。文件选择应绑定同一文档和操作，避免素材落到另一个页面。
- **相邻模块。** 卡片、工作流、HeySure 设备调用及 MCP 管理页共享部分目录或执行器。HeySure 以外部目录为输入并派发到外部网关，文件动作另有 `file_ref` 物化与结果上传。迁移一个动作需覆盖这些消费者的参数、回执、审计脱敏和失败恢复。
- **长期维护。** 不统一目录与执行规则，会在每次新增动作时重复改 schema、模型提示、侧栏白名单、外部适配和卡片代码。将能力及错误定义落在共享服务后，入口只携带权限、取消和传输上下文。用差异测试约束例外的范围和退出条件。

## 当前验证范围

[双入口集成测试](../test/integration/mcp-entry-parity.test.js) 使用真实外部网关与侧栏工具路由，替身提供 Chromium 和站点响应。它保护全部已审计工具的目录及共享 schema，并覆盖标签列表、媒体观察、等待、截图、接管后点击，以及支持的 PNG 元素下载、工作区摘要和文件控件选择。真实 Nova Reel 的链接下载和加号上传仍是 P0 验收项。
