# AI 控制侧栏交互改造：分阶段实施与用户验收

本任务书记录阶段和通过条件。阶段 0–4 的实现与验证记录见[本地验收说明](ai-control-interaction-acceptance.md)。U1–U9 由用户在桌面应用中验收，阶段 5 待确认。

## 1. 目标与边界

借鉴 Codex 的交互逻辑，不追求功能清单或视觉复制。AI-FREE 的目标是让用户在同一段对话里**看清 AI 操作什么、知道任务是否真的完成、直接检查并复用结果**。

**首版主线：在指定标签页取得素材 → 从对话预览 → 重开会话仍可引用同一份产物 → 上传到用户指定的页面 → 核对结果。** 先走通这一条，再扩展工具和文件类型。

- 主入口仍是右侧 `ai-control.html`。窄侧栏默认显示目标、关键状态和结果，详细参数及日志按需展开。不新增独立终端窗口、第二套文件管理器或覆盖首页的视图。
- 复用现有工作区、会话仓库、浏览器接管和自动化卡片。首页「MCP 管理」继续仅供开发者查工具格式及示例；不恢复侧栏设置、MCP 调用上限或完整 Prompt 查看器。
- 首版处理本地聊天和内置浏览器文件链路，优先验收 PNG。外部 MCP 的任意路径、远端产物同步、媒体批量工作台及第三方 Skill 安装不在范围内。
- `AI-Workspace` 不是命令进程的 OS 沙箱；不借改造扩大工具权限，不把网页或附件变成可信指令，不宣称停止命令能回滚已有副作用。

## 2. 阶段与通过条件

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| 0 | 基线和本地验收夹具 | 相同场景可复现旧行为并验证新行为 |
| 1 | 文件输入与自动选择目标 | 引用可核对；目标不可用时不改投其他页面 |
| 2 | 对话文件产物 | 下载、预览、历史恢复、再引用、定向上传形成首版闭环 |
| 3 | 命令执行状态 | 运行中可见日志；停止有实际结果 |
| 4 | 上传确认与核验 | 用户确认文件与目标；未知结果不自动重放 |
| 5 | 可选：Skill 与项目规则 | 用户确认复用需求及规则作用域后另行实施，不阻塞阶段 1–4 的最终验收 |

### 阶段 0：记录基线，准备测试夹具

1. 读取根目录 `AGENTS.md`、[目录与进程边界](architecture/directory-map.md)、[浏览器运行模式](browser-workflow-modes.md)和[浏览器工具对齐说明](codex-browser-alignment.md)。用 `git status --short` 区分既有改动，禁止覆盖无关工作。
2. 从输入框追到请求准备、工具分发、会话保存及历史渲染。记录 `@` 与附件各自的行为、显式连接不可用时的回退、下载返回和停止命令的实际效果。修复旧行为前先增加一条会失败的回归用例。
3. 扩展现有 Electron 验收设施。用独立测试 `userData`、AI-Workspace、浏览器 Profile 和仅监听回环的测试服务。提供素材页 A、上传页 B、干扰页 C，以及两张同名但内容不同的 PNG。B/C 独立记录文件选择、接收次数与内容摘要；B 可模拟一次「已处理，但工具未收到最终确认」。提供本地命令夹具验证延时输出、超时和子进程停止。
4. 自动测试用确定性的工具序列或模型替身，不依赖公网账户或随机模型输出。人工验收从真实侧栏走同一条业务路径。交付时提供可重复的启动/清理命令、测试 URL、测试模式或模型及所需提示语。

### 阶段 1：任务输入与目标选择

- 保留 `@` 与附件入口。选中文件以可移除的文件项表示，同名用相对目录区分。明确是「仅引用位置」还是「附加供 AI 读取」；如果首版仍是选文件即附加，就明确显示，不放未实现的切换按钮。
- 不以 `@文件名` 文本作为授权或唯一标识。以校验后的工作区引用为准；移除文件项后不再注入该文件。保留 `attachmentPaths` 老历史读取能力和现有附件预算；文件缺失时不能静默换成同名文件。
- AI 按本轮任务选择浏览器。多个环境在线时，AI 用 `change_browser` 指定连接。用户可以在消息里说明目标浏览器或网站。指定连接不可用时返回可诊断错误。主进程为每轮工具操作记录原页面，必要时由 AI 指定标签重新观察。
- 页面操作在主进程核验运行时目标。标签索引可变，标题和 URL 也不能作为唯一身份；不复用跨页或历史观察 `ref`。执行时无法保证是原目标就停止操作，由 AI 核对标签后再决定下一步。不改变外部 MCP 的兼容约定。

**阶段门槛：** 同名文件选对、可移除；旧历史可打开；切页、关闭目标、标签索引变化或断开显式 Profile 时，干扰页无误操作，正常目标仍能完成任务。

### 阶段 2：工具产物进入对话

- 只从内置 `browser_media download` 和 `browser_file download/download_element` 的成功结果生成文件引用。主进程以实际完成写入的文件为准；不从助手 Markdown、stdout 或全目录扫描猜测产物。不展示 `save_session` 导出的敏感文件。
- 最小元数据：工作区相对引用、名称、类型、大小、来源调用标识、用于识别路径被替换的下载摘要或可靠版本标记。成功的流式和历史渲染共用这份元数据；限制数量和大小，不保存文件内容、base64、绝对路径或敏感 URL。复用历史仓库及已有同步策略；其他设备无文件时提示不可用，不自动找同名文件。
- 助手消息显示「预览」「再次引用」。预览复用现有工作区预览；再次引用只进入草稿，不自动发送。预览、引用和执行上传前，主进程重新校验真实路径及文件身份，拒绝越界路径、指向工作区外的符号链接和 junction。移动或删除提示文件不可用；替换需要重新选择，不把新文件当旧产物。
- 并发会话不串产物；失败、取消及未完成的下载不生成成功卡片。保留旧会话、工具事件及现有工作区列表，不把产物强制注入之后每一轮上下文。

**阶段门槛：** 从 A 下载 PNG，只从对话预览；重启后在原会话再次引用并定向上传到 B。用测试页回读文件名和摘要。删除、替换、越界不误读、不误传。此阶段只用隔离夹具验通上传；正式的确认和未知结果恢复在阶段 4 交付。

### 阶段 3：命令可见、可停止

- 复用命令卡片与 `run_command`，显示运行、退出、失败、超时、正在停止、已停止或无法确认终止；展示耗时、退出码、有限的实时 stdout/stderr 和截断提示。统一 `timeout_ms` 显示。不引入 PTY 或改变公开工具的参数和最终结果。
- 沿用聊天事件通道，按请求和工具调用定位，限频分批并限制缓冲；收起只显示摘要，不抢焦点或强制滚动。历史只保留有界脱敏摘要，不另外保存完整实时日志。
- 将停止信号传到本地命令的进程生命周期。测试 Windows 子进程树退出及停止、自然退出和超时竞争。确认相应进程终止才显示「已停止」；停止等待不等于停止命令。停止本轮后不再发出下一条工具调用。清理 timer、listener 和受管理进程。

**阶段门槛：** 命令结束前能看到两批间隔输出；非零退出、超时和截断可区分；停止后测试子进程退出，夹具文件不再追加。重开会话不把旧命令画成仍在运行。

### 阶段 4：上传前确认，未知结果先核验

- 第一批只覆盖本地聊天发起的素材上传。确认时显示「哪个文件 → 哪个浏览器/页面」；拒绝不发出动作。确认只适用于该次调用，期间文件、页面或目标改变则失效。覆盖文件、最终提交等其他副作用需单独扩展，不默认纳入这次改造。
- 分清「文件已选入控件」与「站点已接收」；后者需要业务证据。优先复用现有浏览器工作流探针和调试报告，不平行实现一套重试引擎。
- 动作可能已发送但超时或丢回执时，显示「结果待核验」。下一步优先读取业务状态；在未核验前不得自动重新上传、换工具补做或重复提交。无法核验时请用户判断。重开会话不自动继续有副作用的操作。

**阶段门槛：** 取消时 B/C 计数不增，正常上传只增一次；模拟已处理但丢回执，继续操作先核验，计数仍为一次；确认前后切页均不得误操作 C。

### 阶段 5：仅按实际需要增加 Skill 和项目规则

- **Skill 是可重复的方法。** 先从一项用户反复做且需要 AI 判断的任务开始，支持可信内置 Skill 的显式选择、取消和本轮来源提示。固定步骤继续由已有自动化卡片执行，不维护第二份流程或运行状态。第三方安装、自动匹配和隐式扩权不在该阶段最小范围内。
- **项目规则是作用域内持续生效的约定。** 先确认「项目」是不是文件目录。确实服务代码目录时才实现 `AGENTS.md` 发现，明确受信根目录、继承与冲突优先级、来源展示、跨项目隔离及失效处理。普通附件、网页和下载物不得自动作为规则。规则与 Skill 均不能覆盖用户确认或主进程安全边界。
- 用户未批准则标记「未排期」，不放空入口。另行实施时增加「选择/取消 Skill」「切换项目不串规则」「普通附件不成为指令」三项验收。

每阶段只做对应范围。新 IPC 走登记、schema 和窄 preload API；存储变更可读旧数据。优先扩展 `test/unit/ai-chat/` 中的工作区、工具执行、历史与浏览器测试，再覆盖 `test/contract/ipc/preload-domain-api.test.js`、`test/packaging/ai-control-workspace-assets.test.js`、`test/packaging/packaged-runtime-assets.test.js` 和现有 Electron 验收。

3. 阶段交付记录：阶段编号、变更和非目标、复现方式、测试命令及证据、未过/未跑的原因、已知限制。不能用源码测试替代生成态或受影响的打包验证。清理夹具、临时数据、监听和子进程；不把真实凭据写入记录。

## 4. 最终用户手动验收

实现 AI 提供候选版本、实际测试 URL、测试 Profile、夹具启动/清理命令、所用模型或确定性入口、已知限制和自动测试清单。用户用**非开发者模式**在真实侧栏操作；先跑主流程，再跑故障用例。每个独立用例先重置夹具计数与文件状态。

| 编号 | 用户操作 | 通过标准 | 结论 |
| --- | --- | --- | --- |
| U1 | `@` 查找两张同名图，选一张并移除，再选择另一张发送 | 能区分两张图，移除后不发送原选择，最终文件正确 | 待验收 |
| U2 | 在 A 下载 PNG，直接从助手消息预览 | 可见正确图和来源，不用复制路径或另找文件 | 待验收 |
| U3 | 关闭/打开侧栏，切换会话，再退出并重启应用、打开原历史 | 产物仍可预览，未串会话、未重复显示，不自动重跑 | 待验收 |
| U4 | 点历史产物「再次引用」，选 B 并确认上传 | 不自动发送；可核对文件和目标；B 回读匹配的文件，C 无操作 | 待验收 |
| U5 | 运行时切到 C，另测关闭目标页与断开显式 Profile | 在可验证的原目标执行，或停下提示；不改投 C 或首个连接 | 待验收 |
| U6 | 移走下载文件，另测在原路径换成不同图片，打开原对话 | 提示不可用或已更改，不预览或上传错误文件 | 待验收 |
| U7 | 运行夹具的延时命令，分别尝试停止、超时与超长输出 | 结束前看见进度；状态正确；截断可见，已停止后无后续写入 | 待验收 |
| U8 | 取消一次上传确认，再用 B 的丢回执模式上传并继续 | 取消后计数不变；丢回执先核验，B 仍只接收一次，C 为零 | 待验收 |
| U9 | 缩窄侧栏，收展详情、键盘选文件，并打开旧会话 | 信息和操作不重叠；键盘可用；旧记录可读；正常模式没有首页 MCP 管理入口 | 待验收 |

**用户记录：** 候选版本/构建标识、测试日期、每项通过/失败/未测、失败复现、整体结论（通过 / 修复后复验）。证据脱敏。跨页误操作、错误文件上传、重复提交和假停止是阻断问题。自动测试通过只能标记「可提交用户验收」；**最终验收由用户确认**。

## 5. 给实现 AI 的启动指令

> 读取根目录 `AGENTS.md` 和本任务书。先做阶段 0，确认现有改动、基线及本地夹具；再按编号实施，每阶段先提交验证证据和剩余限制。优先完成阶段 1–2 的文件闭环，再做阶段 3–4；阶段 5 等用户确认。阶段 1–4 完成后交付候选版本及 U1–U9 的运行说明，等待用户本人验收，不代填「通过」。
