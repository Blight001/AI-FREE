# 目录重排说明

以下路径均相对于仓库根目录（`package.json` 所在目录）。源码按运行边界划分：

| 目录 | 运行边界 | 典型内容 |
|---|---|---|
| `src/app/backend` | Electron 主进程 | 启动、窗口、IPC、业务服务、Chromium 与系统 IO |
| `src/app/frontend` | 页面进程 | 主窗口 renderer、右侧 sidebar、HTML 页面入口 |
| `src/app/contracts` | 跨进程契约 | IPC channel、payload schema、结果协议 |
| `src/app/shared` | 纯逻辑共享层 | 文本、版本、配额和布局等无副作用工具 |

旧的 `src/app/main`、`src/app/renderer`、`src/app/sidebar` 和 `src/app/views` 已完成迁移；源码构建、测试、Electron 入口和打包资源引用均使用新路径。`backend/preload.js` 仍与主进程入口同目录，作为本轮迁移的兼容边界，后续单独迁移到 `src/app/preload` 时需同步验证三类窗口的生命周期和 CSP。

推荐定位顺序：先按进程边界查 `backend` 或 `frontend`，再按业务域查 `backend/features/<domain>`，最后沿 `contracts` 查 IPC 调用方和注册方。

主窗口首页由 `frontend/views/app-shell.html` 承载，默认显示「浏览器管理」。左侧常用栏目从上到下依次为浏览器管理、账号管理、插件管理和自动化；个人中心上方另设「使用教程和商城」及「设置」快捷入口，个人中心位于左下角。设置快捷入口会切换到个人中心并打开较大的常规设置弹窗；教程、商城入口仍通过原内置 Chromium 浏览器导航。已在首页时，点击底部「首页」保留当前栏目、弹窗及未保存的输入。账号管理包含内置 Google、Microsoft 及自定义栏目，添加表单由主窗口内的同一个模态弹窗承载。每条浏览器记录的「网站数据」打开可搜索的双栏面板，按域名汇总已落盘的 Cookie 记录数和存储桶数，支持复制统计摘要，并可在本机记录之间预览和迁移显式配置的站点图片、声音偏好。偏好引用通过源记录重新取值，应用前校验预览并锁定目标 Profile。网站数据面板可以一次预览并复制所选域名下各来源地址（协议、主机、端口）的第一方默认存储桶 IndexedDB。复制时锁定两个已关闭的 Profile，仅写入目标的对应数据库目录。若目标已有其中一个来源的 IndexedDB，整批停止并提示冲突。Cookie 和其他网页存储仅作统计；个人中心栏目承载登录、资料、套餐和公告；常规设置由上方「设置」快捷入口打开的模态弹窗承载。右侧 `WebContentsView` 始终加载 `ai-control.html`，显隐不会导航；AI 和独立代理弹窗的登录请求通过 `request-account-center` 返回首页个人中心。

首页模态表单和操作确认共用 `#home-dialog-layer`。这一层在首页内容区内居中和裁剪，打开期间仅冻结首页内容，任务栏保留鼠标和键盘交互。点击遮罩空白处会保留弹窗和输入。切换到浏览器时暂时隐藏首页，点击任务栏「首页」返回后继续显示原栏目、弹窗和未保存的输入。首页隐藏期间，Esc 不会关闭首页弹窗。切换首页栏目时关闭原栏目的弹窗。个人中心公告在面板内展开，点击面板外不会收起，切到浏览器再返回时保留展开状态。

左侧栏上方的「使用教程和商城」快捷入口、会员开通按钮和个人中心兑换区「商城」入口复用原教程的 Chromium Profile。教程和商城按需打开各自的网页标签，不另外创建 Electron 窗口。Chromium 用实际标签及其导航记录查找对应入口，包括服务端重定向前的入口地址；没有匹配标签时才新建。后台获取教程配置只更新地址，下次点击教程时应用，不重新加载当前页面。旧教程记录保留原 Profile ID，默认标题迁移为「使用教程和商城」；商城导航不会改写已保存的教程入口。

首页「技能库」读取 AI-Workspace 的 `skills/<name>/SKILL.md`。首次访问目录时提供「添加技能」模板。首页可预览正文或将创建技能引用加入侧栏草稿，聊天加号可搜索、选择及移除技能。发送前按摘要检查文件，正文只加入当轮发给模型的用户消息。

首页「自动化」栏目复用 `BrowserAutomationBridge` 的卡片存储、版本、运行管理器与 MCP router。画布编辑器维护 `steps`、`flow.start`、`flow.edges` 和展示专用的 `flow.layout`；AI 仍通过既有 `manage_card` MCP 能力管理相同对象。第一阶段提供列表、浏览器指定、JSON 导入导出、节点画布、后台运行查看、取消与重试；第二阶段增加步骤边界暂停/继续、单步和软删除回收站。暂停仅在当前进程内有效，退出后的运行标记为中断，不自动重放浏览器动作。

左侧栏目底部的个人中心入口与个人中心共用头像图片和登录状态，显示当前用户名（未登录时显示「未登录」）。点击后切换到首页内嵌的个人中心，不打开新窗口。

密码掩码与账号同排，点击眼睛才从主窗口请求单条密码；离开或切换栏目时收起。已有账号可在同一弹窗中修改或清空备注，不替换凭据。「添加账号」弹窗在备注下方提供「文本导入」，支持分隔行和带 `账号`、`密码`、`邮箱密码` 标签的文本。内置栏目仅接收邮箱，自定义栏目也接受用户名或数字账号；导入只保存经确认的账号和密码，忽略额外令牌、不覆盖已有账号，结果支持逐条确认删除。

账号栏目末尾的加号打开自定义栏目命名弹窗；自定义标签可通过上下文菜单改名或删除，确认删除账号或栏目后，受影响的账号进入回收站。回收站入口在当前栏目的「添加账号」右侧，汇总所有栏目的已删账号，可恢复，彻底删除前需确认，没有自动清理期限。栏目 ID 在改名时保持不变，版本 3 的加密账号库兼容版本 1、2。

账号管理通过单个 `account_manage` MCP 工具提供 `categories`、`list`、`add`、`import`、`update`、`delete`、`trash`、`restore`、`purge` 和 `fill` 操作。例如，列出 Google 账号时传 `{"action":"list","provider":"google"}`。已有自动化卡片中的独立账号工具调用须改用 `account_manage` 并设置对应的 `action`，其余参数沿用。模型读取脱敏账号和引用 ID，可通过引用直接填写已接管的 HTTPS 页面。批量导入使用 AI 编写的本机转换命令，账号库验证统一记录并一次加密提交，模型只收到计数。移入回收站和彻底删除均需本机确认。

`backend/services/` 尚未完全按业务域收敛，里面同时存在窗口/标签服务、跨域桥接和历史模块。目录名不代表这些模块都是通用服务。新逻辑优先放入 `features/<domain>/`；修改既有模块时先确认真实调用方和生命周期，再决定是否迁移，避免复制出第二份实现。

Windows 主窗口的标题栏仅保留拖动区域和最小化、最大化、关闭按钮，不显示图标或名称。首页、内嵌浏览器和 AI 侧栏均在标题栏下方布局；任务栏、托盘和首页的应用标识不变。
主窗口最小化时保留内嵌浏览器上一次布局，恢复时再按当前窗口尺寸同步。

AI 控制侧栏的显隐与宽度记录在 `userData/app-window-state.json`。切换显隐时立即保存，下次启动恢复；没有有效的显隐记录时仍默认展开。

AI 侧栏在剩余额度圆环旁用积分图标和整数显示当前对话及关联子对话已记录的软件端额度，悬停时显示带小数的消耗积分。重新打开历史对话时恢复累计值，自定义 API 不计软件端额度，旧版未保存的扣费无法回填。

侧栏空白对话不展示历史，已保存对话只在历史下拉框显示，可置顶或取消置顶；置顶状态随账号的本机历史保存。消息区位于底部时跟随新内容，向上滚动后保留当前位置，手动滚回底部或点击输入框上方的下箭头可恢复跟随。

AI 对话历史按账号保存在 `userData/ai-chat-history/<scope>/`：`index.json` 只含标题、预览、时间、消息数等摘要；正文按对话 ID 的 SHA-256 文件名独立写入 `sessions/`。旧版 `userData/ai-chat-history/<scope>.json` 首次访问时幂等迁移，新文件回读验证并写入索引后才标记完成，旧文件保留作为恢复源。侧栏 localStorage 仅保存摘要，不缓存正文。超长对话首次只渲染最新 56 条消息，向上分页每次加载 40 条；复制、撤回等操作仍用完整消息数组中的原始索引。

开发模式还显示「调试控制台」首页栏目，不需要登录或打开独立窗口。首页主帧在栏目可见时按需读取最近 500 条内存日志；切换栏目、进入浏览器或隐藏主窗口会停止刷新，返回时重新读取。默认跟踪最新日志，可关闭跟踪以查看旧记录。复制仅包含当前筛选结果；清空移除所有来源的内存记录，不停止后续采集。侧栏不接收日志广播，正式版不保留这份历史。

首页「模型设置」包含「自定义模型」「HeySure 服务器」「MCP 配置」三个内嵌栏目。AI 控制的「添加自定义模型」通过窄 IPC 返回首页并打开新增弹窗，不重载侧栏。自定义模型支持按 OpenAI 兼容接口获取目录并批量添加。HeySure 连接及本机 MCP 配置沿用原有服务，表单只在首页渲染；MCP 密钥由主进程直接写入剪贴板，不返回给页面。此处的「MCP 配置」与开发模式下的「MCP 管理」工具目录独立。开发者可从「MCP 管理」打开独立的「MCP 调试面板」。面板在主窗口最小化时保持可见，随主窗口关闭。鼠标调试绑定活动 HTTP 或 HTTPS 标签页的文档，预览和操作复用共享 MCP 工具。 面板右侧的「MCP 综合基准」只负责启动专用 Chromium Profile 和本机确定性页面，并向 AI 控制侧栏发送一次性测试通知。侧栏以当前选中模型走普通对话链路，用户消息、流式 MCP 事件、最终回复及本机核验成绩保存在同一对话；不另建隐藏 managed chat、不复制会话浏览器或成绩 UI。公网网站测试与本机基准分开。

自定义模型与最近一次手动选择统一保存在 `userData/ai-models.json`（`version: 1`，`aiControlSettings.customApis` 和 `aiControlSettings.lastModelId`）。旧版 `store/content` 的自定义模型会在首次读取时迁移；新版文件成功写入并可读后才清理旧模型字段。API Key 使用操作系统凭据加密；跨系统用户或主机复制时，移除副本里的 `encryptedApiKey` 字段后，在界面重新填写。退出应用后可编辑非敏感配置；不要改写已有模型的稳定 `id` 或直接填写明文 API Key。每个自定义模型的 `streamOutput` 默认开启，可在编辑表单关闭；服务端模型保持默认流式输出。

内置代理通过底部魔法棒打开 `frontend/views/network-magic-popup.html`；再次点击魔法棒或点击窗外会收起弹窗，不改变代理运行状态，正在执行的操作继续运行。关闭代理时仅显示居中的开启按钮。服务启动成功后，按钮移到左上角并变为关闭按钮，再显示模式和右侧按地区分组的双列节点。启动和切换期间锁定控件。电源按钮只由弹窗控制器渲染；共享代理流程提供运行状态，流量配额不改动按钮。

端口、系统和全局模式均由主进程管理代理服务。代理启停、模式切换和选路均保留每个内置浏览器的代理配置与标签页状态。使用端口代理时，由用户在浏览器环境配置中填入本地监听地址；系统和全局模式仍管理 Windows 系统代理，浏览器按自身代理设置决定是否跟随系统。

侧栏的 MCP 子会话由 `backend/features/ai-chat/managed-chat-service.js` 管理，通过 `platform/managed-chat-repository.js` 保存加密运行记录。AI 侧栏仅在当前父对话中显示其子任务卡片。普通对话和任务对话共用消息区模板、消息渲染、工具卡片和滚动行为。子会话视图只读，底部仅展示用量和模型；运行由委派方通过 `chat_session` 控制。子会话运行中的展示事件和保存的回复快照只通过侧栏任务状态提供。切换子会话时保留父对话 DOM、草稿和滚动位置。

## 常用术语

| 术语 | 本项目中的含义 | 不要与之混淆 |
|---|---|---|
| 浏览器环境（Profile） | 一组独立设置、存储和 Chromium 进程的业务实体，以 `profileId` 标识 | Chromium 网页标签索引 `tab_id` / `index` |
| 应用标签（App Tab） | AI-FREE 窗口顶部管理的浏览器环境入口；当前 ID 与 `profileId` 对应 | Chromium 内部网页标签 |
| Browser Runtime | 主进程管理 Chromium 进程、Profile、命令通信和嵌入窗口的运行层 | Electron renderer 或普通网页运行时 |
| Runtime Bridge | AI-FREE Chromium 与主进程之间的认证本机协议/命名管道 | `BrowserAutomationBridge` 本机 HTTP MCP 服务 |
| Browser Automation Bridge | 主进程中的自动化应用服务，组合浏览器工具、卡片运行和外部 MCP 网关 | Runtime Bridge 传输协议本身 |

主进程启动、浏览器启动和自动化调用的端到端关系见[项目路径图](project-paths.md)。Chromium 子系统的启动事务、标识符、配置应用语义与资源所有权见 [Chromium 运行层接手说明](browser-runtime.md)。
