# 添加技能

从用户的任务或当前对话中提取三个要点：以后遇到什么请求时使用、用户会提供什么、怎样判断结果可用。信息足够时直接编写；只有会改变技能用途的歧义才需要追问。

在当前 AI-Workspace 的 skills 下为新技能建立一个目录。目录名与文件头的 name 一致，使用小写英文字母、数字和单个连字符。新增时先检查同名目录；已有同名技能时保留原文件，说明冲突，并给出针对当前任务的其他名称。

在新目录写入 UTF-8 的 SKILL.md。YAML 文件头至少包含 name 和 description。用用户的语言说明适用场景和产出，需要中文显示名时写入 metadata.ai-free-title。正文写下会影响结果的操作、取舍和验收条件。仅在任务确实需要模板或详细规则时创建 assets 或 references，并在正文中用相对路径指向对应文件。

例如，用户希望复用一次会议纪要整理流程，应保留其指定的输出字段和负责人缺失时的处理方式。示例使用虚构内容，避免将当次会议的参与者、附件路径或凭据保存成通用指令。

保存后从磁盘读回文件，核对目录名、文件头、正文以及引用的资源。向用户给出实际文件位置和一句可以试用的新请求。只有实际运行并检查过输出，才报告行为验证通过。
